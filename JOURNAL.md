# Accountability Template — Python in 90 Days

Copy a fresh **Daily Entry** block at the end of each day.
Copy a fresh **Weekly Retro** block at the end of each week (every 7 days).
Keep this file in the same repo as the tracker. Commit it daily — the journal *is* the receipt.

---

## How to use this

- **Time it:** 5–10 minutes for daily, 20–30 minutes for weekly. Don't let it balloon.
- **Be honest, not heroic.** "I didn't understand list comprehensions today" is more valuable than "Great progress!"
- **Write before you stop for the day**, not the next morning. Recall decays fast.
- **The weekly retro is non-negotiable.** Skipping it is how 90-day plans quietly die in week 4.

## Daily Entry — Day ___ / 90

**Date:** ____________
**Hours worked:** ____
**Tracker checkboxes ticked today:** ____________

### 1. What I built / learned today
*(2–4 sentences. Concrete: "Wrote a `LeagueTable` class that groups results by team using `defaultdict`." Not vague: "Learned more Python.")*

### 2. What confused me
*(Anything I had to look up twice, copy from Stack Overflow, or still don't fully understand. This is the most valuable part of the entry — it's tomorrow's study list.)*

### 3. Today's commit(s)
*(Repo + commit message. If I didn't commit, why not?)*

### 4. Tomorrow's first task
*(One specific thing. Not "continue Phase 2." Something like "Read McKinney ch. 5.2 on `groupby` and rewrite my bet tracker analysis using it.")*

### 2. What didn't work
*(Where did I get stuck? Did I cheat the plan? Skip tests? Copy code I didn't understand? Be specific.)*

### 3. The one concept that finally clicked
*(There should be at least one per week. If there isn't, I'm not pushing hard enough OR I'm rushing past things I don't understand.)*

*(Carry it into next week explicitly. Don't let it pile up.)*

### 5. Commits this week
*(Count: ____ / 7. If under 7, what got in the way?)*

### 6. Adjustments for next week
*(Schedule changes, resource swaps, scope cuts. The plan is a guide, not a contract — but adjustments should be deliberate, not drift.)*

### 7. Confidence check (1–5)
- Phase content this week: ____
- Building toward the capstone: ____
- Overall sustainability of the pace: ____

*(If sustainability drops below 3 two weeks in a row, the plan needs a real re-scope — talk to Claude about it.)*

## End-of-Phase Review (every ~3 weeks)

Run this after Week 3, Week 7, Week 10, and Week 13.

1. **Can I rebuild this phase's mini-projects from scratch without notes?** If no, which one is weakest? Spend a day redoing it.
2. **Could I explain this phase's key idea to a peer in 5 minutes?** (Phase 1: "Pythonic idioms." Phase 2: "Vectorized data manipulation." Phase 3: "Probabilistic modeling and calibration." Phase 4: "End-to-end data pipeline.")
3. **What from this phase will the capstone actually use?** Mark it. The rest is context, not foundation.
4. **What habit did I form this phase that I want to carry forward?**

---

## Final Review — Day 90

1. Walk through the repo as if I were a hiring manager. What would they see? What's missing?
2. The capstone: does it actually work end-to-end on data it has never seen? Run it on a held-out season.
3. Compare the JS Betting Engine to the Python edition. Where is the Python version better? Where is it worse? Be honest.
4. What's the next 90 days? (Don't stop here — momentum is the asset.)
